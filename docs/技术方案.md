# 充电精灵 ChargeTone 技术方案

> 目标机型：一加 Ace 2 Pro / ColorOS 16（Android 16）
> 版本：MVP v0.1.0

## 一、已确认的产品决策

| 决策项 | 结论 | 原因 |
|---|---|---|
| 可靠性路线 | **前台服务常驻 + 动态注册接收器** | 插拔广播不在隐式广播豁免清单内，清单接收器收不到（见第二节），只能靠存活进程监听 |
| 音频通道 | **通知音量**（`USAGE_NOTIFICATION_EVENT` / `CONTENT_TYPE_SONIFICATION`） | 静音、勿扰模式下由系统静音，符合"手机静音时不响"的直觉 |
| 音频存储 | SAF 选择后**复制**进 `filesDir/tones/` | 原文件被删、移动或重启后 URI 授权失效都不影响提示音 |
| 配置存储 | DataStore Preferences + 内存热缓存 | 广播回调需要同步读取，故加一层缓存 |

## 二、关键发现：插拔充电器广播收不到（实测）

Android 8.0 起，**隐式广播**不再投递给清单声明的接收器，豁免清单里
**没有** `ACTION_POWER_CONNECTED` / `ACTION_POWER_DISCONNECTED`
（见 [隐式广播例外情况](https://developer.android.com/guide/components/broadcast-exceptions)、
[后台执行限制](https://developer.android.com/about/versions/oreo/background)）。

Android 11 模拟器上的实测结论（系统日志 `Background execution not allowed: receiving Intent { act=android.intent.action.ACTION_POWER_CONNECTED ... } to com.chargetone.app/.power.PowerReceiver`）：

| 方案 | 前台可见 | 切后台 | 进程被回收 | 常驻通知 |
|---|---|---|---|---|
| 清单接收器 + targetSdk 34 | ❌ | ❌ | ❌ | 无 |
| 动态注册接收器（Application 里注册） | ✅ | ✅ | ❌ | 无 |
| 清单接收器 + targetSdk 25 | ✅ | ✅ | ✅（系统重启进程） | 无 |
| **动态注册接收器 + 前台服务（当前方案）** | ✅ | ✅ | ✅（`START_STICKY` 重启服务） | 1 条 |

targetSdk 25 方案实测可用且无通知，但需要放弃 Play 上架、并依赖 Google 保留
"targetSdk < 26 豁免"这一兼容行为，属于不可控的技术债；最终选择官方路线。

```

├── power/

└── ui/

    ├── MainScreen.kt           监听开关、两个槽位、试听、音量、事件、说明
    └── theme/Theme.kt
```

### 事件流

```
用户开启「后台监听服务」
        ▼
ChargingService.startForeground() + ChargingMonitor.start()（动态注册）
        ▼
系统广播 ACTION_POWER_CONNECTED / DISCONNECTED（进程存活才收得到）
        ▼
ChargingEventHandler
   ├─ 用粘性 BATTERY_CHANGED 读 EXTRA_PLUGGED → AC(1)/USB(2)/无线(4)
   ├─ ChargingStateMachine：同状态丢弃、1200ms 内翻转丢弃
   ├─ 读设置：开关、音效文件名、音量系数
   ├─ 静音模式 → 跳过（通知通道被系统静音）
   └─ PlaybackEngine：prepareAsync + PARTIAL_WAKE_LOCK(20s) → 播完释放
```

## 四、关键实现细节

1. **前台服务类型**：`android:foregroundServiceType="specialUse"`，并声明
   `PROPERTY_SPECIAL_USE_FGS_SUBTYPE=charging_state_monitor`。
   Android 14+ 要求声明类型与 `FOREGROUND_SERVICE_SPECIAL_USE` 权限。
2. **启动时机**：Android 12+ 禁止后台启动前台服务，因此服务只在两种时机启动：
   用户点击界面开关（前台）、`BOOT_COMPLETED`（受系统限制，失败会降级为提示）。
3. **保活**：`onStartCommand` 返回 `START_STICKY`，进程被系统回收后自动重建服务。
   实测：`am crash` 后进程重建、服务恢复前台、通知重新出现。
4. **状态判定单一来源**：`ACTION_BATTERY_CHANGED` 是粘性广播，用
   `registerReceiver(null, filter)` 同步读取 `EXTRA_PLUGGED`；`POWER_*` 广播只作触发器。
5. **去重**：`ChargingStateMachine` 用 `lastConnected: Boolean?` 表示"状态未知/已接入/已断开"，
   首次事件必定采纳；同状态重复事件与 1200ms 内的翻转一律丢弃。
6. **同步读配置**：`SettingsCache` 由常驻 Flow 填充；进程刚拉起时缓存为空，
   回退到 `runBlocking { settings.first() }`（小文件，毫秒级）。
7. **唤醒锁**：播放期间持 `PARTIAL_WAKE_LOCK`，20s 超时兜底，异常路径不泄漏。
8. **音量**：`setVolume(percent/100f)` 是在系统通知音量之上的额外衰减，滑块 0~100%。
9. **通知**：`IMPORTANCE_MIN` + `setSilent(true)` + `setOngoing(true)`，
   提供「停止监听」动作（同时把 `monitorEnabled` 置为 false）。

## 五、权限

| 权限 | 用途 |
|---|---|
| `WAKE_LOCK` | 息屏播放期间保持 CPU 唤醒 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE` | 常驻监听服务 |
| `POST_NOTIFICATIONS` | Android 13+ 显示前台服务通知（拒绝也不影响服务运行） |
| `RECEIVE_BOOT_COMPLETED` | 开机恢复监听 |

## 六、已知限制

1. **不能替换 ColorOS 自带充电音**，只能额外播放；需用户手动关闭系统音效。
2. **必须有常驻通知**：受限制广播只能由存活进程接收，这是系统约束。
3. **静音 / 勿扰模式不响**：通知通道被系统静音，属预期行为。
4. **重启后未解锁**：未启用 `directBootAware`，此场景暂不支持。
5. **ColorOS 后台清理**：需允许自启动、电池"不限制"、允许后台运行，
   否则服务被杀后需要重新打开应用。这是失败率最高的环节，已做引导文案。
6. **极短插拔间隔**：1.2s 内的二次状态翻转会被当作抖动丢弃。
7. 开机恢复在 Android 15+ 可能被系统拦截（部分 FGS 类型不允许从
   `BOOT_COMPLETED` 启动），代码已捕获异常并降级为"打开应用自动恢复"。

## 七、验证记录

### 7.1 Android 11 模拟器（sdk_gphone_x86）

| 场景 | 结果 |
|---|---|
| 清单接收器收插拔广播 | ❌ 系统日志 `Background execution not allowed` |
| 动态接收器（前台 / 后台） | ✅ 正确识别"有线 AC"与"未连接电源" |
| 前台服务开启（通知出现、状态"运行中"） | ✅ |
| 息屏 + 切后台 + 插电 | ✅ `播放提示音：test_tone_e67b4b.wav` |
| SAF 选择音频 → 复制到 `files/tones/`（52,964 字节） | ✅ |
| 进程崩溃后 `START_STICKY` 重建服务 | ✅ 新进程 + 通知恢复 |
| 关闭开关 → 服务停止、通知消失 | ✅ |
| 重启后开机自动恢复（`am_proc_start ... BootReceiver` → 服务前台 → 通知入栏） | ✅ |
| 开机后息屏插电仍播放 | ✅ |

### 7.2 真机（PJA110 / 一加 Ace 2 Pro，ColorOS 16 / Android 16 / API 36）

| 场景 | 结果 |
|---|---|
| 安装（targetSdk 34 应用装在 Android 16 上） | ✅ |
| 通知权限（Android 13+ 运行时权限） | ✅ 用户授权后通知可见 |
| 前台服务常驻 | ✅ `isForeground=true types=0x40000000`（`specialUse`） |
| 真实插入 USB / 拔出 | ✅ `检测到接入充电器（USB）` → `播放提示音` |
| 息屏状态下插拔真实充电器 | ✅ 用户确认能听到提示音 |
| AC（充电器）识别 | ✅ `检测到接入充电器（有线 AC）` |
| 充电音 / 断开音分别生效、无重复播放 | ✅ 各自播放对应文件 |
| 覆盖安装升级后设置与音效保留 | ✅ `files/tones/` 与 DataStore 均保留 |

真机遇到并修正的问题：

1. 广播回调瞬间粘性电池状态可能尚未刷新，接入事件曾被记成"未连接电源"——
   现在对"已接入但类型未知"单独标注，不再给出误导性描述。
2. 每次回到前台都会重复打印"后台监听服务已启动"——改为仅在真正首次启动时记录。

> 说明：真机测试中 adb 与充电共用 USB 口，拔线做充电测试时 adb 会断开，
> 因此事件日志以手机端 logcat 缓冲区与 App 内「最近事件」为准。

## 八、构建方式

```powershell
cd F:\projects\CNS
.\gradlew.bat :app:assembleDebug
# 产物：app\build\outputs\apk\debug\app-debug.apk
.\gradlew.bat :app:testDebugUnitTest    # 状态机单元测试
.\gradlew.bat :app:installDebug         # 需连接手机并开启 USB 调试
```

工具链：JDK 17、AGP 8.5.2、Gradle 8.7、Kotlin 2.0.21、compileSdk 34、minSdk 26、targetSdk 34。
