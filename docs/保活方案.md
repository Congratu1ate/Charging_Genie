# 长时间后台存活方案（参考 GKD）

> 状态：**v0.2.2 已编译、已装真机并完成授权验证**（2026-11-18）。
> 仍需观察 1~2 天，确认 `o-kill` 是否消失、插拔是否恢复即时响应。

## 一、问题实测结论

一加 Ace 2 Pro / ColorOS 16 上，前台服务进程仍会被 ColorOS 的 **o-kill** 定期回收：

```
ApplicationExitInfo:
  reason=13 (OTHER KILLS BY SYSTEM)  importance=125（前台服务级）
  description=o-kill(4012) / o-kill(37)
  频率：11 月 17 日 11:45、11:50、11:59、12:54、13:54、15:23、17:36、22:35 …
```

进程被杀后，插拔广播只能靠系统**冷启动**拉起应用，于是表现为「过一会儿才响」，被限流时「完全不响」。

另外两条独立机制（不要混淆）：

| 机制 | 表现 | 日志特征 |
|---|---|---|
| HANS 墓碑冻结 | 进程冻结、不响应，解冻后才处理 | `OplusHansManager freeze uid: <uid>` |
| o-kill | 进程被直接杀死 | `ApplicationExitInfo` 中 `o-kill(xxxx)` |

已排除项：`RUN_ANY_IN_BACKGROUND` 已是 allow；`deviceidle` 白名单已加；`appops set` 需要 root，不可行。

## 二、GKD 的做法（源码依据）

| 层 | GKD 源码 | 要点 |
|---|---|---|
| 无障碍服务 | `service/A11yService.kt` | 系统绑定宿主，主要执行体 |
| **1×1 透明悬浮窗** | `platform/overlay/KeepAliveOverlayCoordinator.kt` | `width=1,height=1,alpha=0`、`FLAG_NOT_TOUCHABLE\|FLAG_NOT_FOCUSABLE`、`TYPE_APPLICATION_OVERLAY`；在 Application → 无障碍服务 → 特权服务之间**接力持有** |
| 前台状态通知 | `service/StatusService.kt` + `LifecycleHookService.kt` | 常驻通知显示运行状态，`NotificationDispatcher.startForeground` |
| 快捷设置磁贴 | `service/GkdTileService.kt` 等 | 通知栏一键查看/重启服务 |
| 电池白名单 | `ui/settings/KeepAlivePage.kt`、`ignoresBatteryOptimizations()` | 引导用户设为「不限制」 |
| 特权模式（可选） | `priv/`（Shizuku / root，`WRITE_SECURE_SETTINGS`） | 改系统设置兜底，普通模式不需要 |

关键点：`SYSTEM_ALERT_WINDOW` 持有者是 Android 12+ **后台启动前台服务的官方豁免项**，
且国产 ROM 的电管策略通常不清理「有可见窗口」的进程。接力持有避免单点失效。

## 三、本项目的实现（已完成代码，待编译验证）

| 文件 | 作用 |
|---|---|
| `service/ChargingKeepAliveService.kt` | 可选无障碍服务：不读屏、不处理事件，仅保活；连上后顺带拉起前台服务 |
| `service/KeepAliveOverlay.kt` | 1×1 全透明悬浮窗，服务启动时挂上、销毁时释放 |
| `service/ChargingTileService.kt` | 快捷设置磁贴：显示运行状态、一键启停 |
| `service/ChargingJobScheduler.kt` | `JobScheduler` 兜底：`requiresCharging` 一次性任务 + 15 分钟巡检任务 |
| `service/ChargingWatchJobService.kt` | 兜底任务执行体：服务不在时补播充电音并拉起服务 |
| `ui/MainScreen.kt` | 新增「极限保活（可选）」卡片：无障碍状态/授权入口、悬浮窗授权入口、磁贴提示 |

设计约束：

- 无障碍与悬浮窗**都是可选**，默认关闭；不授权时应用仍按纯前台服务工作
- 无障碍配置 `canRetrieveWindowContent=false`，不做任何辅助操作
- 悬浮窗 `alpha=0`、1×1、不可触摸，用户不可见
- JobScheduler 任务只在 `MonitorStatus.running == false` 时动手，避免与实时监听重复

## 四、真机验证记录（v0.2.2，PJA110 / ColorOS 16）

| 检查项 | 结果 |
|---|---|
| 编译 / 单元测试 | ✅ `BUILD SUCCESSFUL` |
| 前台服务（新渠道 `charging_monitor_v2`，LOW） | ✅ `isForeground=true types=0x40000000` |
| 1×1 悬浮窗 | ✅ `dumpsys window` 可见 `Window{… com.chargetone.app}`，`appop=SYSTEM_ALERT_WINDOW` |
| 无障碍服务 | ✅ `Enabled services` 含 `com.chargetone.app/…ChargingKeepAliveService` |
| JobScheduler 巡检任务（4102） | ✅ `PERIODIC PERSISTED`，周期 15 分钟 |
| JobScheduler 上电任务（4101） | ⏳ 充电中按设计不排期，拔电后自动武装 |
| 界面状态显示 | ✅ 「无障碍保活：已开启」「悬浮窗保活：已授权」 |

踩坑记录：

1. `Settings.ACTION_ACCESSIBILITY_DETAILS_SETTINGS` 在 compileSdk 34 不可用，改用 action 字符串 + 回退到无障碍总列表。
2. **`am force-stop` 会连带停用无障碍服务**（系统行为）。调试时不要 force-stop；若已发生，重新打开应用并在无障碍里重新启用。
3. 无障碍可用 adb 写入：`settings put secure enabled_accessibility_services "<原有>:com.chargetone.app/com.chargetone.app.service.ChargingKeepAliveService"`，
   但悬浮窗权限只能用户在设置里授予（`appops set` 需要 MANAGE_APP_OPS_MODES）。
